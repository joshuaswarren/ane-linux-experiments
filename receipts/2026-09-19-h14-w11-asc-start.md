## 2. Stage 2 — bring-up mechanism: kernel RTKit mapped, gap written down

Sources read (exact): `include/linux/soc/apple/{rtkit,mailbox,sart}.h`
from `linux-asahi-headers 7.1.13.asahi3-1` (headers-only package —
`drivers/soc/apple/` ships just `Kconfig`; the running kernel carries
`apple-mailbox/apple-rtkit/apple-rtkit-helper/apple-sart/apple-dart`
as **builtin**, `modules.builtin` entries, with only `aop.ko` and
`apple-tunable.ko` as real `.ko` files), plus upstream
`drivers/soc/apple/{rtkit.c,mailbox.c,rtkit-helper.c}` (Asahi `asahi`
branch) and m1n1 `proxyclient/m1n1/hw/asc.py`.

What `apple_rtkit_init()` + `apple_rtkit_boot()` require (all
`drivers/soc/apple/*`, function-level provenance):

- **Transport handle**: `apple_rtkit_init(dev, cookie, mbox_name,
  mbox_idx, ops)` → `apple_mbox_get_byname()` → `of_parse_phandle_with_args(dev->of_node, "mboxes", "#mbox-cells", …)` (`mailbox.c`). The client DT node MUST carry `mboxes` (+ optional `mbox-names`). The ANE node has neither.
- **Mailbox device**: `apple_mbox_probe()` binds a node with
  `compatible = "apple,asc-mailbox-v4"` (of-match table, `mailbox.c`
  bottom), one `reg` (0x4000; live siblings e.g. `mbox@2a9408000` =
  `0x2a9408000/0x4000`), and FOUR named IRQs
  `send-empty/send-not-empty/recv-empty/recv-not-empty`
  (`platform_get_irq_byname("recv-not-empty")` is a hard `-ENODEV`
  gate). Register layout is fixed: `a2i_control 0x110`,
  `i2a_control 0x114`, `a2i_send0/1 0x800/0x808`, `i2a_recv0/1
  0x830/0x838` — the exact offsets W10 confirmed live at
  `0x285408110/114/800/808/830/838`.
- **Boot sequence** (`rtkit.c:apple_rtkit_boot`, `rtkit-helper.c:probe`):
  helper ioremaps reg-names `"asc"` + `"sram"`, writes
  `CPU_CONTROL_RUN (BIT 4)` at `asc+0x44` (m1n1 `ASC.boot()` is the
  same single line; `R_CPU_STATUS`: RUNNING=0, STOPPED=1), then calls
  `apple_rtkit_wake()` → `apple_rtkit_boot()`, which waits on the
  firmware's EP0 HELLO, answers HELLO_REPLY (proto v11/12), collects
  EPMAP, waits for the IOP power ACK, and sends SET_AP_PWR_STATE ON.
  The firmware speaks first — W10's fw-first intuition matches the
  code path exactly — but only after the CPU runs firmware.
- **Shared memory**: `shmem_setup` serves RTKit buffer requests either
  via `dma_alloc_coherent` (iova==0) or by carving the `sram` reg
  region (MTP template: `reg-names = asc sram`, sram =
  `0x2a9c00000/0x100000`). `apple,sart` (`sart@34bc50000`,
  `apple,t6020-sart`) is consumed only by `nvme@34bcc0000` on this
  SoC — no ANE/SART link exists.

The ANE node (`/proc/device-tree/soc/ane@284000000`) against that
template:

| RTKit needs | ANE node has | sibling proof it works |
| --- | --- | --- |
| `mboxes` phandle | **absent** | mtp/smc/gpu/dcp/aop all carry one |
| mailbox `mbox@2854…` node | **absent** (no `285408000` node; ANE reg covers `0x284000000/0x2000000` with no 0x4000 mbox window carved) | 10 live `apple,asc-mailbox-v4` nodes, all bound to `apple-mailbox` |
| `reg-names` incl. `asc`/`sram` | `engine pmgr set` only | mtp: `asc sram`; smc: `smc sram`; gpu: `asc sgx` |
| `memory-region` (fw shmem) | **absent** | gpu: 6 regions; dcp: 3; isp/sio present |
| mailbox IRQs (4) | one IRQ `ane`, raw AIC 884 | every mbox node: 4 named IRQs |
| `compatible` RTKit-helper match | `apple,t6021-ane` only | mtp: `apple,rtk-helper-asc4` (bound, `RTKit: Initializing (protocol version 12)` in dmesg) |

**The gap**: no `mboxes`, no mailbox node, no `memory-region`/`sram`,
no helper-compatible, single IRQ. Wiring `ane_drv.c` to the kernel
RTKit core requires (i) the `selene_rc4x` firmware image — absent per
§1, and (ii) a DT overlay adding the mailbox node + `mboxes` +
`memory-region` + helper match (SRAM size/placement for ANE unknown;
MTP's 1 MiB sram is the only template, not evidence). Both
prerequisites are unresolved, so Stage 3 was not started and no overlay
was written.
