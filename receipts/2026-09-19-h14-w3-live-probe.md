# H14/T6021 W3 — live module probe on jw14m2: gate + resource legs clean, forced bind walled at the first ASC status-block read (2026-09-19)

Verdict: **CAPTURED-STOP.** The W3 skeleton `ane_t6021.ko` loaded on the real
device end to end up to a named line: refusal gate holds, the -EBUSY resource
leg was fixed and pushed, and the forced bind raised six power domains, read
the full pmgr island chain and the SET window safely — then the **first read
inside the ANE engine block (ASC status stage, RVBAR at block+0x1050000 =
0x285105000)** stalled `insmod` for ~60 s and the box reset below the kernel.
pstore empty (no panic path), the last netconsole line is the named stage
banner. No retry (runbook discipline + W2 lane rule: only a real t6021 source
moves this lane).

**Attribution upgrade over W1:** this death is NOT the periodic hardware
wedge. Boot0 died at **~6-7 min uptime** (W1 instances: 6h10m, 3h05m, 3h43m),
and the same boot survived the gate and -EBUSY legs minutes earlier with zero
device contact. The kill is the engine-block access.

## 3. What this pins (and what it doesn't)

- **Third independent kill datum, same class**: W2 killed at the first read
  of the old +0x1c04000 sub-window (0x285c2400c); W3 kills at the first read
  of the block-relative ASC block (0x285105000). Two different windows,
  same signature: **first host read inside 0x284000000+32 MiB external-aborts
  t6021**, while satellite windows (pmgr islands, SET) read safely and the
  six-domain genpd raise completes. The whole-block-is-mapped premise is
  falsified at the hardware level regardless of which sub-offset is touched
  first.
- Set+0 = 0 again (matches W2): the live SET-block location remains
  unverified.
- ANE CPU island (`pmgr+0x2e0`) reads `1f0003ff` — nonzero state bits,
  unlike the six `+0x4000` islands (`000003ff`). Recorded verbatim in the
  netconsole artifact; not interpreted further (no capture source).
- NOT distinguishable from this pass alone: whether the ASC read needs the
  firmware alive first (kext order: RTBuddy up before block walks) or the
  block needs a power state no DT chain expresses. W2's rule stands: no
  guessing another offset — m1n1 walk or a macOS-side engine-window capture
  is the only unblock.
