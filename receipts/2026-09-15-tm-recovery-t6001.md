## Root-cause chain (all register-backed)

1. `ane_tm_enable` was a partial transcription of m1n1
   `ANETaskManager.reset` (`TQ_EN |= 0x1000` vs m1n1's `0x3000`). Necessary
   hygiene, **not** the idle-bit cause: with `0x3000` (commit `f3ad6e5`) the
   smoke still ran to completion (`finish lines=3`) while TM_STATUS stayed
   `0x0`.
2. The T6001 tm/tq register file survives the recovery cycle. kprobe + rpm
   trace: `pm_runtime_force_suspend` on the five attached pd_devs does reach
   `apple_pmgr_ps_power_off → ps_set` (the gate writes happen), yet tmpeek
   after recovery still read `TQ4 SIZE1=0x7d0000 PRTY=0x5` — submit-era
   values, not reset values. Retention, not a wiped file.
3. The register file lives behind **set0 and base**, the first two words of
   the ane SET block (`0x28e08c000+0x00/+0x08`). Neither carries a genpd
   consumer on T6001 (attached = sys_cpu, set1..4 only), so the recovery
   never gated them. Gate-depth proof: with the module unloaded (all
   islands ACTUAL=0), tmpeek read the file **clean** (`TQ4` all zero) and
   `TM_STATUS=0x1` — idle is the hardware reset value; from this state the
   09-13 100/100 soak passed.
4. Consequence: after recovery the wedged task's queue state persists and
   the tm never reports idle; healthy submits complete (finish events fire,
   `finish lines=3`) but `*finished == 3 && (TM_STATUS & TM_IS_IDLE)` never
   becomes true → every submit -110s → wedge → auto-recover loop.
